**답부터.** 한국은행 ECOS 오픈API는 **가입 없이도 지금 바로 테스트할 수 있습니다.** 인증키 자리에 `sample`을 넣으면 실제 데이터가 돌아옵니다(최대 10건). 아래 주소를 브라우저에 그대로 붙여보십시오 — 한국은행 기준금리가 나옵니다.

```
https://ecos.bok.or.kr/api/StatisticSearch/sample/json/kr/1/5/722Y001/D/20261101/20261112/0101000
```

**ECOS에서 사람들이 막히는 지점은 인증키가 아니라 코드입니다.** 통계표코드가 `722Y001` 같은 형태라, 기준금리를 받고 싶어도 그 코드를 찾다가 포기합니다. 이 글의 핵심은 **실제로 호출해서 확인한 코드표**입니다.

| 질문 | 한 줄 답 |
|---|---|
| **인증키는?** | 회원가입 시 자동 발급. 발급 직후에는 `INFO-100`이 올 수 있다. 그 전에는 **`sample`로 테스트**(10건 한도) |
| **코드는 어디서?** | 아래 코드표를 복사하면 되고, 없는 지표는 `StatisticTableList`·`StatisticItemList`로 찾는다 |
| **빈 응답이 나오는데?** | 대개 **주기(D/M/Q/A)와 날짜 형식이 안 맞거나** 항목코드가 틀린 경우다. 에러 코드로 구분된다 |

## 답부터: 요청 URL 한 줄 해부

ECOS는 **URL 경로에 파라미터를 순서대로 끼워 넣는** 방식입니다. 쿼리스트링(`?key=value`)이 아니라서 순서를 틀리면 바로 에러가 납니다.

```
https://ecos.bok.or.kr/api/StatisticSearch/{인증키}/json/kr/1/100/{통계표코드}/{주기}/{시작}/{종료}/{항목코드}
```

| 칸 | 값 | 설명 |
|---|---|---|
| 서비스명 | `StatisticSearch` | 아래 6종 중 하나 |
| 인증키 | 발급키 또는 `sample` | `sample`은 10건까지 |
| 요청유형 | `json` / `xml` | json 권장 |
| 언어 | `kr` / `en` | |
| 시작·종료 건수 | `1` / `100` | 페이징. `1/100`이면 1~100번째 |
| 통계표코드 | `722Y001` | 어느 통계표인가 |
| 주기 | `D` `M` `Q` `A` 등 | 아래 표 참조 |
| 검색 시작·종료 | `20261101` / `20261112` | **주기에 맞는 형식**이어야 한다 |
| 항목코드 | `0101000` | 통계표 안의 어느 항목인가 |

주기 코드와 날짜 형식은 짝이 맞아야 합니다.

| 주기 | 코드 | 날짜 형식 | 예 |
|---|---|---|---|
| 연 | `A` | `YYYY` | `2024` |
| 반년 | `S` | `YYYYS1` · `YYYYS2` | `2024S1` |
| 분기 | `Q` | `YYYYQ` | `2024Q1` |
| 월 | `M` | `YYYYMM` | `202610` |
| 반월 | `SM` | `YYYYMMS1` · `YYYYMMS2` | `200401S1` |
| 일 | `D` | `YYYYMMDD` | `20261112` |

참고로 **반년(`S`)과 반월(`SM`)을 쓰는 통계표는 각각 하나뿐**입니다(`S`는 `105Y001`, `SM`은 `814Y002`). 실무에서 만나는 것은 사실상 `D`·`M`·`Q`·`A` 네 가지입니다.

## 바로 쓰는 통계표코드 표

**아래 코드는 전부 실제로 호출해서 응답을 확인한 것입니다.** 확인값은 2026년 11월 13일 조회 기준이고, 호출 URL은 위 형식에 그대로 끼워 넣으면 됩니다. `DATA_VALUE`는 문자열로 오므로 기준금리는 `"3"`처럼 돌아옵니다 — 표에도 응답 그대로 적었습니다.

| 지표 | 통계표코드 | 항목코드 | 주기 | 단위 | 확인값 |
|---|---|---|---|---|---|
| **한국은행 기준금리** | `722Y001` | `0101000` | `D` `M` `Q` `A` | 연% | 3 (2026-11-11) |
| **국고채(3년)** | `817Y002` | `010200000` | `D` | 연% | 3.729 (2026-11-11) |
| **국고채(10년)** | `817Y002` | `010210000` | `D` | 연% | 3.95 (2026-11-11) |
| **원/미국달러(매매기준율)** | `731Y001` | `0000001` | `D` | 원 | 1,343.3 (2026-11-11) |
| **원/일본엔(100엔)** | `731Y001` | `0000002` | `D` | 원 | 846.44 (2026-11-11) |
| **원/유로** | `731Y001` | `0000003` | `D` | 원 | 1,500.47 (2026-11-11) |
| **원/위안(매매기준율)** | `731Y001` | `0000053` | `D` | 원 | 201.74 (2026-11-11) |
| **소비자물가지수(총지수)** | `901Y009` | `0` | `M` `Q` `A` | 2020=100 ※ | 120.73 (2026-10) |
| **CPI 식료품·비주류음료** | `901Y009` | `A` | `M` `Q` `A` | 2020=100 | 129.49 (2026-10) |
| **본원통화(평잔, 계절조정)** | `102Y004` | `ABA1` | `M` `A` | 십억원 | 311,149.3 (2026-08) |
| **M2(평잔, 원계열)** | `161Y006` | `BBHA00` | `M` `Q` `A` | 십억원 | 4,257,820.8 (2026-08) |

※ 소비자물가지수는 **2026년 12월 18일 2025년 기준으로 개편 공표 예정**입니다. 그 뒤에는 단위가 `2025=100`으로 바뀌고 지수 수준도 리셋됩니다.

세 가지만 짚어두겠습니다.

**첫째, 환율은 일별(`D`)만 됩니다.** `731Y001`을 월(`M`)로 요청하면 빈 응답이 옵니다. 항목이 53개(주요국 통화)라 통화만 바꿔 쓰면 됩니다.

**둘째, 같은 통계표에서 항목만 바꾸면 다른 지표가 나옵니다.** `817Y002`는 시장금리(일별) 통계표라 국고채·통안증권·CD 등이 항목으로 들어 있고, `901Y009`는 항목이 **581개**입니다(총지수·식료품·교통 등 품목별 전체). `StatisticItemList`가 1,743행을 돌려주지만 이건 **항목 × 주기(A·M·Q) 행 수**라서, 실제 항목은 그 3분의 1입니다.

**셋째, 2차 자료의 코드표를 그대로 믿지 마십시오.** 널리 인용되는 한 문서는 **명세 샘플데이터 칸에서** `102Y004`를 "평잔, 원계열"로 적어뒀지만 지금 API 응답은 **"평잔, 계절조정계열"**입니다(원계열은 현재 `102Y002`). 계절조정 여부는 분석 결과를 바꿉니다.

다만 **그 문서가 틀렸다기보다 코드가 재배정된** 쪽으로 보입니다. 그 문서가 적은 계층번호(`1.1.1.1.2.`)까지 현재의 `102Y002`와 짝이 맞기 때문입니다. ECOS는 「1.1. 통화/유동성(신지표) 통계표 변경 안내」(2025-12-30)처럼 코드 변경 공지를 계속 올립니다. **남의 코드표는 그 글이 쓰인 시점의 체계입니다** — 쓰기 전에 한 번 호출해 확인하는 게 맞습니다.

## 코드를 모를 때 찾는 법

위 표에 없는 지표는 두 단계로 찾습니다.

**1단계 — 통계표 찾기: `StatisticTableList`**

```
https://ecos.bok.or.kr/api/StatisticTableList/sample/json/kr/1/10
```

`STAT_NAME`이 `1.1.1.1.1.`처럼 번호로 시작하는 것은 ECOS 웹사이트의 메뉴 계층과 같습니다. **웹에서 원하는 통계표를 먼저 찾고 그 이름으로 코드를 맞추는 쪽이 빠릅니다.**

**2단계 — 항목 찾기: `StatisticItemList`**

```
https://ecos.bok.or.kr/api/StatisticItemList/sample/json/kr/1/10/731Y001
```

그 통계표가 가진 항목코드와 **각 항목이 지원하는 주기**가 함께 나옵니다. 주기를 여기서 확인하는 것이 핵심입니다 — 통계표는 월 단위인데 항목은 일 단위만 있는 경우가 있습니다.

## 서비스 6종 — 뭘 언제 쓰나

| 서비스명 | 하는 일 | 쓸 때 |
|---|---|---|
| `StatisticSearch` | **통계 데이터 조회** | 실제 숫자를 받을 때. 가장 많이 쓴다 |
| `StatisticTableList` | 통계표 목록 | 통계표코드를 모를 때 |
| `StatisticItemList` | 통계 세부항목 목록 | 항목코드와 지원 주기를 확인할 때 |
| `KeyStatisticList` | **100대 통계지표** | **코드 없이 주요 지표를 한 번에** 받을 때 |
| `StatisticMeta` | 통계메타DB | 통계의 작성 기준·출처를 볼 때 |
| `StatisticWord` | 통계용어사전 | 용어 뜻을 찾을 때 |

**이 중에서 가장 과소평가된 것이 `KeyStatisticList`입니다.** 통계표코드도 항목코드도 필요 없습니다.

```
https://ecos.bok.or.kr/api/KeyStatisticList/sample/json/kr/1/10
```

호출하면 **101개 주요 지표**가 분류명·지표명·값·단위와 함께 한 번에 옵니다. 실제 응답을 보면 이런 식입니다.

| 분류 | 지표 | 값 | 기준 |
|---|---|---|---|
| 통화량 | M1(협의통화, 평잔) | 1,351,852.9 십억원 | 2026-08 |
| 통화량 | **M2(광의통화, 평잔)** | **4,257,820.8 십억원** | 2026-08 |
| 환율 | 원/달러 환율(종가) | 1,330.7 원 | 2026-11-12 |
| 채권 | 국고채발행액 | 21,228 십억원 | 2026-08 |
| 소득 | GDP(명목, 계절조정) | 834,925.1 십억원 | 2026 2분기 |
| 가계 | 가구당월평균소득 | 6,969.4 천원 | 2024 4분기 |

**대시보드를 만들 목적이라면 이 하나로 상당 부분이 끝납니다.** 코드를 찾기 전에 값만 빨리 확인하는 용도로도 좋습니다.

참고로 **이름은 "100대"인데 실제 응답은 101행**입니다. 직접 호출해 보면 바로 보입니다.

## 자주 막히는 지점 — 에러 코드로 구분한다

빈 응답이 왔을 때 추측하지 말고 에러 코드를 보십시오. **실제로 틀린 요청을 보내 받아낸 코드들입니다.**

| 코드 | 메시지 | 원인과 해법 |
|---|---|---|
| `INFO-100` | 인증키가 유효하지 않습니다 | 키 오타, 또는 발급 직후 아직 활성화되지 않은 상태 |
| `INFO-200` | 해당하는 데이터가 없습니다 | **가장 흔하다.** 통계표코드·항목코드 오류, 또는 그 기간에 데이터가 없음 |
| `ERROR-101` | 주기와 다른 형식의 날짜 형식입니다 | 일별(`D`)에 `2026`을 넣은 식. 주기와 날짜 형식을 맞출 것 |
| `ERROR-301` | 조회건수 값의 타입이 유효하지 않습니다 | `sample` 키는 **최대 10건**이다. 그 이상은 발급키로 |

**`INFO-200`이 특히 헷갈립니다.** "코드가 틀렸다"와 "그 기간에 데이터가 없다"를 같은 코드로 주기 때문입니다. 순서대로 좁히십시오.

1. **기간을 넓혀본다** — 월별 지표를 최근 1~2개월로 조회하면 아직 공표 전일 수 있습니다
2. **`StatisticItemList`로 항목코드와 주기를 확인한다** — 항목 목록에 있는 코드인지, 그 주기를 지원하는지
3. **`StatisticItemList`의 `START_TIME`·`END_TIME`을 본다** — **가장 흔한 함정이 구(舊)계열 통계표입니다.** M2를 `101Y004`로 조회하면 최근 기간이 비어 나오는데, 이 표의 `BBHA00`은 `END_TIME`이 **`200409`로 2004년에 끝난 구계열**입니다. 현행 M2는 **`161Y006`**(`1.1.3.1.2. M2 상품별 구성내역(평잔, 원계열)`)의 `BBHA00`이고, 월별로 2026-08까지 정상 조회됩니다(**4,257,820.8 십억원**). **빈 응답이 오면 코드를 의심하기 전에 기간부터 맞춰보십시오** — 항목 목록이 그 통계표의 유효 기간을 알려줍니다

## 파이썬으로 받아 표로 만들기

표준 라이브러리만 써서 돌아가는 최소 코드입니다. 인증키 자리에 `sample`을 넣으면 그대로 실행됩니다.

```python
import json
import urllib.request

KEY = "sample"          # 발급 후 본인 키로 교체
BASE = "https://ecos.bok.or.kr/api/StatisticSearch"

def ecos(stat, cycle, start, end, item, rows=10):
    # sample 키는 10건까지. 기간을 넓히면 뒤가 조용히 잘린다
    url = f"{BASE}/{KEY}/json/kr/1/{rows}/{stat}/{cycle}/{start}/{end}/{item}"
    with urllib.request.urlopen(url, timeout=20) as r:
        try:
            data = json.load(r)
        except json.JSONDecodeError:
            # 서비스명을 틀리면 JSON이 아니라 HTML 오류 페이지가 온다
            raise RuntimeError("JSON이 아닌 응답 — 서비스명을 확인하십시오")
    if "RESULT" in data:                      # 에러 응답
        raise RuntimeError(data["RESULT"]["CODE"] + " " + data["RESULT"]["MESSAGE"])
    return data["StatisticSearch"]["row"]

# 한국은행 기준금리 (일별)
for row in ecos("722Y001", "D", "20261105", "20261112", "0101000"):
    print(row["TIME"], row["DATA_VALUE"], row["UNIT_NAME"])
```

응답 필드는 아래가 전부입니다. 이름이 길어 보이지만 쓰는 것은 네 개뿐입니다.

| 필드 | 내용 |
|---|---|
| `STAT_CODE` / `STAT_NAME` | 통계표코드·이름 |
| `ITEM_CODE1~4` / `ITEM_NAME1~4` | 항목코드·이름. 다차원 통계표는 2~4까지 쓴다 |
| **`TIME`** | 시점. 주기에 따라 `20261112` 또는 `202610` |
| **`DATA_VALUE`** | **값.** 문자열로 오므로 `float()` 변환이 필요하다 |
| **`UNIT_NAME`** | 단위. `연%`, `원`, `2020=100`, `십억원` 등 |
| `WGT` | 가중치(물가지수 등) |

`DATA_VALUE`가 문자열이라는 점을 놓치면 집계에서 조용히 틀립니다. 그리고 **`UNIT_NAME`을 확인하지 않으면 지수와 금액을 섞게 됩니다** — 소비자물가지수는 `2020=100`인 지수이고 통화량은 `십억원`입니다.

## 클로드 코드로 자동 조회하기

반복 조회는 스크립트를 짜기보다 AI 코딩 도구에 맡기는 쪽이 빠릅니다. 요령은 **ECOS의 규칙을 먼저 알려주는 것**입니다. 그러지 않으면 코드를 지어내거나 주기를 틀립니다.

프롬프트에 아래 네 가지를 넣으십시오.

| 알려줄 것 | 내용 |
|---|---|
| URL 형식 | `/api/{서비스}/{키}/json/kr/{시작}/{끝}/{통계표}/{주기}/{시작일}/{종료일}/{항목}` 순서 |
| 주기·날짜 짝 | `D`=`YYYYMMDD`, `M`=`YYYYMM`, `Q`=`YYYYQn`(Q1~Q4), `A`=`YYYY` |
| 코드 확인 절차 | **코드를 추측하지 말고** `StatisticTableList`·`StatisticItemList`로 먼저 확인하라고 명시 |
| 에러 처리 | `RESULT` 키가 있으면 에러. `INFO-200`이면 항목·주기부터 다시 확인 |

**"코드를 추측하지 말라"는 지시가 가장 중요합니다.** ECOS 코드는 규칙성이 약해서, 모델이 그럴듯한 코드를 만들어내면 `INFO-200`만 반복됩니다. 테스트 단계에서는 `sample` 키를 쓰게 하면 발급 전에도 검증이 됩니다.

같은 방식으로 전자공시를 다룬 사례는 [DART API를 클로드코드로 자동 조회하는 글](/blog/2026-06-20-dart-api-claude-code/)에 정리해 뒀습니다.

## ECOS와 FRED를 같이 쓸 때

한국 지표는 ECOS, 미국 지표는 **FRED**(세인트루이스 연준)가 사실상 표준입니다. 금리 차나 물가 흐름을 비교하려면 둘을 붙이게 되는데, 설계에서 걸리는 지점이 셋 있습니다.

| 항목 | ECOS | FRED |
|---|---|---|
| 코드 체계 | 통계표코드 + 항목코드 **두 단계** | 시리즈 ID **한 단계**(예: `CPIAUCSL`) |
| 날짜 표기 | 주기별로 다름(`202610`, `2026Q1`) | **`YYYY-MM-DD`로 통일** |
| 파라미터 | URL **경로**에 순서대로 | 쿼리스트링(`?series_id=...`) |

그래서 두 소스를 함께 쓸 때는 **먼저 각자의 형식으로 받아온 뒤, 날짜와 단위를 한 규격으로 바꿔 합치는 순서**가 안전합니다. ECOS의 `202610`을 `2026-10-01`로 바꾸고, 지수인지 금액인지를 `UNIT_NAME`으로 확인해 열 이름에 단위를 박아두면 나중에 섞이지 않습니다.

비교 지표를 고를 때는 **정의가 같은지**를 먼저 확인해야 합니다. 한국 소비자물가지수는 `2020=100`이고 미국 CPI는 `1982-84=100`입니다 — **기준 시점이 40년 가까이 떨어져 있습니다.** 게다가 한국은 5년마다 기준년을 갈아 지수 수준이 리셋됩니다. 지수 자체를 나란히 놓으면 의미가 없고, **전년 대비 변화율로 바꿔야 비교가 됩니다.**

## 정리 — 순서대로 하면 막히지 않는다

1. **`sample` 키로 먼저 돌려본다.** 가입 전에 형식을 익히는 데 10건이면 충분합니다
2. **위 코드표를 복사한다.** 기준금리·국고채·환율·물가는 그대로 쓰면 됩니다
3. **없는 지표는 `StatisticTableList` → `StatisticItemList` 순서로 찾는다.** `SRCH_YN`이 `Y`인 것만 조회됩니다
4. **대시보드라면 `KeyStatisticList`부터 본다.** 코드 없이 101개 지표가 한 번에 옵니다
5. **빈 응답은 에러 코드로 구분한다.** `INFO-200`이면 항목코드와 주기를, `ERROR-101`이면 날짜 형식을 봅니다
6. **`DATA_VALUE`는 문자열, `UNIT_NAME`은 꼭 확인한다**

ECOS가 불친절하게 느껴지는 이유는 **데이터가 부족해서가 아니라 입구가 코드로 잠겨 있어서**입니다. 617개 통계표에 품목별·지역별 세부 항목까지 들어 있으니, 코드를 찾는 두 단계만 익히면 국내 거시지표는 대부분 자동으로 받을 수 있습니다.
