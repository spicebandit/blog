**답부터. 정부24 오픈API로는 증명서를 발급받을 수 없다. 통계와 서비스 정보만 나온다.**

"정부24 가족관계증명서 발급 API 개발"로 검색해 들어왔다면, 먼저 알려줄 것이 있다. **찾고 있는 그 API는 없다.**

정부24가 오픈API를 제공하는 건 맞다. 그런데 거기서 나오는 건 **민원 처리 건수 통계와 서비스 안내 정보**다. 증명서 원본이 아니다.

증명서를 프로그램으로 받는 길은 따로 있고, **셋 다 기관 자격이 필요하다.** 개인 개발자가 키 발급받아 바로 호출하는 구조가 아니다.

| 흔한 질문 | 한 줄 답 |
|---|---|
| 정부24 API로 증명서 받나 | **못 받는다.** 통계·서비스 정보만 |
| 그럼 어떻게 받나 | **공공 마이데이터** 또는 **전자증명서** — 둘 다 기관 승인 필요 |
| 개인 개발자도 되나 | **직접은 안 된다.** 그리고 **법인이어도 자격이 안 될 수 있다** |
| 얼마나 걸리나 | 공공 마이데이터 승인 통보 **최대 3개월** |
| 무료인가 | API 자체는 무료. 다만 **자격 심사가 관문**이다 |

## 정부24 오픈API로 실제 되는 것

답부터: **통계 네 개와 공공서비스 정보 하나. 그게 전부다.**

정부24 오픈API 페이지에 공개된 목록이다. 공식 명칭 그대로 적는다.

| 공식 명칭 | 내용 |
|---|---|
| 행정안전부_**통계연보**_정부24 민원서비스 사무 종류 | 사무 종류별 **통계** |
| 행정안전부_**통계연보**_정부24 민원서비스 | 민원서비스 **통계** |
| 행정안전부_**통계연보**_정부24 주요 **민원발급** 건수 | 많이 찾는 민원의 **발급 건수 통계** |
| 행정안전부_**통계연보**_보조금24 | 보조금24 **통계** |
| 행정안전부_**대한민국 공공서비스 정보**(보조금24) | 부처·지자체·공공기관 **혜택 정보** |

**이름에 '통계연보'가 붙은 것이 넷**이다. 다섯 번째만 실제 서비스 정보를 준다.

**셋째 줄을 특히 보자.** 공식 명칭은 "주요 **민원발급** 건수"다. '증명서'가 아니다. **발급 건수 통계는 있고, 발급 기능은 없다.**

신청 대상은 넓다. 정부24는 **"정부·공공기관, 민간기업 및 국민 누구나"** 신청할 수 있다고 안내하며, 신청은 **공공데이터포털(data.go.kr)**을 통해 한다.

**그런데 이걸로 할 수 있는 일은 분석이다.** "어떤 증명서가 많이 발급되는가", "어떤 민원이 늘고 있는가", "내가 받을 수 있는 보조금이 무엇인가" 같은 질문에 답할 수 있다.

**증명서 자체를 받아 서류 제출을 자동화하는 일은 이 API로 안 된다.**

### 그래서 이건 오늘 시작할 수 있다

답부터: **자동승인이다. 신청하면 바로 키가 나온다.**

증명서 쪽과 가장 다른 점이 여기다. 아래는 **'행정안전부_대한민국 공공서비스 정보(보조금24)'**(공공데이터포털 15113968) 기준이다.

| 항목 | 내용 |
|---|---|
| 승인 방식 | **자동승인** (개발·운영 모두) |
| 비용 | **무료** |
| 개발 계정 호출 한도 | **1만 건** |
| 운영 계정 증량 | **활용사례 등록 후 신청** |
| 형식 | REST · JSON + XML |
| 제공기관 | 행정안전부 |

**자동승인에 1만 호출.** 뒤에서 볼 공공 마이데이터의 '최대 3개월'과 비교하면 완전히 다른 세계다. **같은 부처가 제공하는 API인데도 그렇다.** 데이터의 민감도가 그 차이를 만든다.

**다만 위 표를 전체에 그대로 적용하면 안 된다.**

| | 승인 | 개발 한도 | 형식 |
|---|---|---|---|
| 공공서비스 정보(15113968) | 자동승인 | 1만 건 | JSON + XML |
| 통계연보 계열 | 자동승인 | 1만 건 | **XML 전용** |
| **공공서비스 공동활용 OpenAPI** | **심의승인** | **1,000건** | XML·HTML·엑셀 |

**마지막 줄이 함정이다.** `gov.kr/openapi` 아래에는 공공데이터포털 자동승인 체계와 **별개 시스템**이 하나 더 있다. 공공서비스 공동활용 OpenAPI(`api.korea.go.kr`)인데 **심의승인이고, 개발 한도가 1,000건이며, 이용기간이 2년**이다. 같은 경로에서 출발했는데 여기 도달하면 **심의를 기다려야 하고 한도는 10분의 1**이다.

시작 순서는 이렇다.

1. **data.go.kr** 회원가입
2. 원하는 API 상세 페이지에서 **활용신청**
3. 자동승인되면 **마이페이지에서 인증키 확인**
4. 상세 페이지의 **API 명세(Swagger·가이드 문서)**에서 요청 주소와 파라미터 확인
5. 호출

**4번을 건너뛰지 말자.** 공공 API는 엔드포인트와 파라미터 이름이 개편되는 일이 있어서, 블로그에 적힌 주소를 그대로 쓰면 404를 만난다. **항상 상세 페이지의 최신 명세를 보고 붙이는 게 맞다.**

## 증명서를 받는 길 ① 공공 마이데이터

답부터: **일정이 문제가 아니다. 자격부터 걸린다.**

이게 정석 경로다. 정보 주체(본인)가 제공을 요구하면, **이용기관**이 API로 그 사람의 행정정보를 받아 쓰는 구조다. 여러 서류를 한 번에 제출하는 서비스가 여기서 나온다.

### 먼저 확인할 것 — 내가 이용기관이 될 수 있나

**가장 많이 오해하는 지점이다. "법인이면 신청할 수 있다"가 아니다.**

이용기관이 될 수 있는 자는 **「전자정부법」이 유형을 열거**하고 있다. 행정안전부 수행 가이드는 이용기관을 이렇게 정의한다.

> 제3자(**행정기관등, 신용정보회사, 신용정보집중기관, 의료기관, 전기통신사업자 등**) 중 제공시스템과 연계하고 행정안전부장관의 승인을 얻은 자

법률이 직접 든 것은 **행정기관등**과 **은행법에 따라 인가받은 은행**이고, 나머지는 **대통령령·행정안전부령으로 정하는 자**로 위임돼 있다. 시행령은 신용정보회사와 신용정보집중기관 등을 추가한다.

**그래서 일반 IT 법인이나 SaaS 스타트업은 이 열거에 들지 않으면 신청 자체가 안 된다.** 보안 체계를 잘 갖춰도 안 된다. **일정을 잡기 전에 내 업종이 대상에 들어가는지부터 확인해야 한다.** 이게 틀리면 3개월이 아니라 사업 설계가 흔들린다.

반대로 **행정기관등은 이미 이용기관 지위를 얻은 것으로 간주**돼 별도 절차 없이 묶음정보 서비스를 쓸 수 있다. **아래 심사 절차는 민간기관 이야기다.**

### 묶음정보 — 조합을 내가 못 만든다

**핵심 개념이 '묶음정보'다.** 특정 서비스를 이용하는 데 필요한 행정정보를 묶어 놓은 세트다.

**행정안전부 장관의 승인을 받은 묶음정보에 한해서만** 쓸 수 있고, 그 승인은 **심의위원회의 심의·의결을 거쳐** 이뤄진다. 내가 원하는 항목을 골라 조합할 수 없다는 뜻이다.

### 서류는 두 묶음으로 나뉜다

**이것도 오해가 많다. 한 번에 다 내는 게 아니라 별개의 두 승인이다.**

**[1] 이용기관 신청** — 2종 + 증빙

| 서류 |
|---|
| 「본인정보 이용기관 신청서」(별지 제1호) |
| 「본인정보 이용기관 **환경 조사표**」(별지 제2호) |

여기에 **증빙 서류**가 붙는다. 법인이면 **사업자등록증 사본과 3개월 내 발행 법인 등기사항증명서**, 단체면 정관 또는 규약과 대표자·관리자 증명 서류다.

**[2] 묶음정보 신청** — 3종

| 서류 |
|---|
| 묶음정보 정의서 |
| 묶음정보 이용·해지 신청서 |
| 「묶음정보 활용 서비스 **업무 분석도**」 |

### 절차에 '현장실사'가 있다

순서는 **이용기관 신청 → 현장실사 → 이용기관 심사(심의위원회)**다.

**현장실사가 들어간다는 점을 일정에 반영해야 한다.** 기관 내규, 시스템 환경 구성, 보안 현황을 **실제로 방문해 검토**한다. 서류만 보내고 기다리는 절차가 아니다.

제출 경로는 셋이다 — **업무포털(adm.mydata.go.kr)의 '본인정보 상시신청 서비스'**, 그 외의 경우 **행정안전부**, 이용지원기관을 경유하면 **해당 분야 이용지원기관**이다.

**통보 기한은 최대 3개월이다.** 정확히는 "신청서를 제출한 날로부터 3개월 이내에 서면으로" 승인 여부를 통보받는다. **소요 기간이 아니라 행정청이 답을 줘야 하는 법정 상한**이라, 더 빨리 나올 수도 있다. 다만 일정은 상한으로 잡는 게 안전하다.

### 기술 연계

표준 규격에 맞춰 **「본인정보 요청 API 세트」와 「본인정보 수취 API 세트」를 연계·설치**해야 한다. 요청 세트에는 묶음정보 발급 신청을 포함해 **24개 API**가 들어 있고, **수취 세트는 이용기관이 직접 설치**한다. 개발 공수를 가늠할 때 이 구분이 중요하다.

**정리하면 이렇다. 개인 개발자가 주말에 붙여볼 수 있는 API가 아니다.** 법령이 정한 기관 유형에 해당하고, 현장실사를 통과하고, 분기 단위 일정으로 들어가는 일이다.

## 증명서를 받는 길 ② 전자증명서(전자문서지갑)

답부터: **서버인증서를 보유한 기관·법인만 표준 API를 쓸 수 있다.**

전자증명서발급유통시스템(dpaper.kr)은 전자문서지갑으로 증명서를 발급·유통하는 체계다. API가 제공된다. 다만 자격 조건이 명확하다.

> **"서버인증서 기반의 서버를 보유한 기관·법인만 표준 API를 이용할 수 있다."**

**개인 개발자는 직접 연동할 수 없다.** 이게 이 경로의 입구에서 걸리는 조건이다.

**신청 절차는 5단계다.**

| 단계 | 내용 |
|---|---|
| 1 | **행정안전부 행정정보공유과**에 공문(우편 또는 문서24)으로 'API 이용 신청서' 제출 |
| 2 | dpaper.kr에서 기관 정보로 신청 |
| 3 | 포털 관리자가 **개발용 API 승인·반려** 심사 |
| 4 | 승인되면 **API 키와 지갑 주소**를 받아 테스트 |
| 5 | 관리자가 테스트 결과를 검토한 뒤 **운영용 인증키** 발급 |

포털 회원 가입이 필요하고, **인증키는 API 기능별로 따로 발급된다.**

**공공 마이데이터와 비교하면 이렇다.** 마이데이터는 "여러 서류를 묶어서 한 번에 받는" 쪽이고, 전자증명서는 "증명서 문서 자체를 전자문서로 주고받는" 쪽이다. 하려는 일이 서류 제출 간소화라면 마이데이터, 전자문서 유통이라면 전자증명서다.

## 증명서를 받는 길 ③ 민간 대행 서비스

답부터: **존재하지만 주의할 점이 많다. 직접 스크래핑은 권하지 않는다.**

본인인증을 받아 증명서 열람·발급을 대행해주는 **민간 서비스**들이 있다. 기관 자격 없이 쓸 수 있고 붙이기도 빠르다. 유료다.

**다만 세 가지를 먼저 따져야 한다.**

**① 법적 근거가 무엇인지.** 이용자 본인의 위임을 어떻게 받고, 그 범위가 어디까지인지가 서비스마다 다르다. 계약서와 약관을 읽어야 한다.

**② 개인정보 처리 책임이 누구에게 있는지.** 여기서 흔한 오해를 하나 짚는다. **가족관계증명서는 개인정보보호법상 '민감정보'가 아니다.** 민감정보는 사상·신념, 건강, 성생활, 유전정보, 범죄경력, 생체인식정보 등으로 **법이 열거**하고 있고 가족관계는 거기 없다.

**대신 더 센 규제가 걸린다.** 가족관계증명서에는 주민등록번호가 들어가므로 **「고유식별정보」**에 해당하고, 제24조(고유식별정보 처리 제한)와 **제24조의2(주민등록번호 처리 제한)**가 적용된다. 주민등록번호는 **법령에 근거가 없으면 정보주체의 동의를 받아도 처리할 수 없다.** 민감정보보다 오히려 강한 제한이다.

**③ 안정성.** 공식 API가 아닌 방식이면 정부 사이트가 개편될 때마다 끊긴다.

**그리고 직접 스크래핑은 다른 문제다.** "소지가 있다"가 아니라 **약관이 명문으로 금지한다.** 정부24 이용약관(시행 2026년 3월 9일) 금지행위 조항이다.

> **제9호** — 사전 허락 없이 자동화된 수단(매크로, 스크래핑 등)을 이용하여 당 사이트가 제공한 서비스에 로그인을 시도 또는 로그인하는 행위(**인증정보를 이용하여 로그인 후 개인정보를 수집하는 행위를 포함**)
>
> **제10호** — IP를 지속적으로 변경하며 … 접속 또는 **캡챠(CAPTCHA)를 외부 솔루션 등을 통해 우회하거나 무력화 하는 행위**
>
> **제7호** — 다른 사용자의 개인정보를 수집 또는 저장하는 행위

*출처: 정부24 이용약관, 시행 2026. 3. 9.*

**"사용자 인증정보를 받아 로그인해 개인정보를 수집하는 행위"가 괄호 안에 그대로 적혀 있다.** 여기에 위에서 본 주민등록번호 처리 제한까지 겹친다. 이 글은 그 방법을 다루지 않는다. **당장 되는 것처럼 보여도 서비스로 운영할 수 있는 길이 아니다.**

## 그래서 내 경우는 어떻게 하나

답부터: **하려는 일이 '분석'이면 지금 바로, '서류 수집'이면 기관 자격부터다.**

| 하려는 일 | 답 |
|---|---|
| 민원·증명서 **발급 통계 분석** | **정부24 오픈API.** data.go.kr에서 신청, 바로 됨 |
| 내가 받을 **보조금 찾기** | **보조금24 API.** 바로 됨 |
| 고객의 **서류를 받아 심사 자동화** | **공공 마이데이터.** 단 **법령이 열거한 기관 유형**인지 먼저 확인 |
| 증명서를 **전자문서로 주고받기** | **전자증명서.** 서버인증서 보유 법인만 |
| **개인 프로젝트로 내 증명서 받기** | **방법 없음.** 정부24에서 직접 발급받는 게 유일 |
| 급하게 **PoC만** 해보기 | 민간 대행 서비스 검토 (약관·개인정보 확인 후) |

**마지막 줄이 중요하다.** 개인이 토이 프로젝트로 자기 증명서를 API로 받아보는 길은 **현재 없다.** 그게 이 글의 가장 중요한 결론이다.

## 왜 이렇게 막아놨나

답부터: **증명서는 데이터가 아니라 신분 증명이기 때문이다.**

주식 시세나 날씨 데이터는 틀려도 손해가 제한적이다. **가족관계증명서는 다르다.** 누군가의 가족 구성이 유출되면 되돌릴 방법이 없고, 위조된 증명서가 유통되면 계약·상속·금융이 흔들린다.

그래서 설계가 이렇게 돼 있다.
· **승인된 묶음정보만** 받을 수 있다 — 필요한 것만 주고 나머지는 안 준다
· **서버인증서 보유 기관만** 연동할 수 있다 — 누가 받았는지 추적 가능하게
· **본인이 요구해야** 전달된다 — 기관이 임의로 조회하지 못한다
· **현장실사 + 최대 3개월** — 보안 체계를 방문해서 실제로 보고 판단한다

**불편한 게 아니라 의도된 설계다.** 이걸 알고 가면 "왜 이렇게 복잡하냐"에 쓰는 시간을 아낄 수 있다.

실무 관점의 조언은 두 가지다.

**첫째, 자격부터 확인하라.** 일정보다 먼저다. 내 업종이 법령 열거에 안 들어가면 아무리 준비해도 안 된다. 이걸 뒤늦게 알면 사업 설계를 다시 해야 한다.

**둘째, 자격이 된다면 신청을 제일 앞에 걸어라.** 현장실사와 최대 3개월을 개발 일정 뒤에 붙이면 사업이 밀린다. 먼저 걸어두고 그동안 나머지를 만드는 게 맞다.

## 정리

**정부24 오픈API는 열려 있지만, 증명서는 그 문으로 나오지 않는다.**

| | 정부24 오픈API | 공공 마이데이터 | 전자증명서 |
|---|---|---|---|
| 얻는 것 | **통계·서비스 정보** | **본인 행정정보 묶음** | **전자증명서 문서** |
| 자격 | **누구나** | **법령이 열거한 기관 유형** | 서버인증서 보유 기관·법인 |
| 승인 | 포털 신청(대부분 자동) | **현장실사 + 최대 3개월** | 행안부 공문 + 포털 심사 |
| 개인 개발자 | **가능** | 불가 | 불가 |

찾던 답이 아닐 수 있다. 하지만 **없는 API를 찾아 며칠 헤매는 것보다는 낫다.** 분석이 목적이면 오늘 시작할 수 있고, 서류 수집이 목적이면 지금 신청을 걸어야 한다.

*이 글은 2026년 10월 2일 기준 정부 공식 안내 페이지와 행정안전부 발행 수행 가이드를 확인해 작성했다. 이용기관 자격은 「전자정부법」과 하위 법령이 정하며 개정될 수 있으니, **실제 판단은 국가법령정보센터의 현행 조문으로 확인하기 바란다.** 공공 서비스의 자격 요건과 절차는 변경될 수 있으니, 실제 신청 전에 각 기관 공식 페이지에서 최신 내용을 확인하기 바란다. 특정 민간 서비스를 추천하거나 권유하지 않는다.*
